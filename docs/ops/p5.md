# P5 operations: media, booking, offers, events

Localhost is the acceptance target. The VM rsync and the public GHL workflow URL wait for go-live.

## Media

ffmpeg with `libwebp`, `libvpx-vp9`, and `libx264` is required (`ffmpeg -encoders`). The Homebrew ffmpeg 9.0.1 bottle on this machine has VP9 and H.264 and does not include `libwebp`, so frame and poster commands fail until that encoder is present. Intermediates go to `media-out/` (git-ignored). `publish` copies them to `public/media/<hash>/` (also git-ignored) and prints manifest URLs of the form `/media/<hash>/...`.

Creating an appointment on API version `2021-07-28` returns an id and no start or end. The client reads the event once to fill those in. The version header is unchanged.

```bash
bun scripts/media/cli.ts extract-frames path/to/clip.mp4 ch1 [path/to/clip-9x16.mp4]
bun scripts/media/cli.ts make-poster path/to/clip.mp4 ch1
bun scripts/media/cli.ts make-loop path/to/hero.mp4
bun scripts/media/cli.ts manifest ch1
bun scripts/media/cli.ts publish
```

`publish user@host:/srv/media` also rsyncs to `<that>/<hash>/`. Omit the argument on localhost.

Each chapter's desktop frames must be ≤ 8 MB and mobile frames ≤ 4 MB. The command exits non-zero when a budget is exceeded. Frame sets are not committed; `bun run check:assets` only sees files git tracks under `public/`.

## Booking, offers, events

- `GET /api/v1/booking/slots?from&to&tz` rejects ranges over 31 days and caches each triple for 60 seconds.
- `POST /api/v1/bookings` with `Idempotency-Key` returns 201, 202 when GoHighLevel returns 5xx, or 409 `slot_taken`. A repeated key replays 201 or 202. Appointments are created without `ignoreFreeSlotValidation`. The contact is tagged `stage:call-booked` and the opportunity moves to Call Booked.
- `GET /api/v1/offers` reads custom values and products. The SDK uses axios, so the response is cached with `unstable_cache` for 10 minutes under the tag `offers`.
- `POST /api/v1/events` appends to `integration.event_buffer`. The worker job `ghl.events.flush` runs every 5 minutes, writes each known email once, and deletes anonymous rows older than 30 days.
- `POST /api/webhooks/ghl-workflow/<GHL_WORKFLOW_SECRET>` compares the key in constant time, dedupes on payload `id` plus `timestamp` when present, and on `offer-changed` expires the `offers` tag.

- A failure after the appointment exists keeps the outbox row and returns 201. The visitor has that time; the worker finishes the tag and stage, or records why it couldn't.
- Booking locks use their own small pool (`getBookingLockPool`), so 10 bookings at once can't exhaust the main pool and freeze.

Apply the index migration with `bun scripts/migrate.ts` after `bun run db:up`.

Set `GHL_WORKFLOW_SECRET` (at least 24 characters) in the local `.env` before posting to the webhook route. Pointing the real GHL workflow at a public URL is a go-live step.
