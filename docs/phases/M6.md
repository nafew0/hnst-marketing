# M6: Calendar, Mail and Notes (owner: Astra, Wave C, about 4 days, alongside M5)

> Paste `docs/RULES.md`, then the phone rules block in `docs/phases/PHONE.md` § 3, then this file, as the first message in the coder's session. Before coding, read `AGENTS.md`, `docs/PLAN.md` § Satus adaptations (§ E5 covers the phone layout) and `docs/phases/PHONE.md`.

**Depends on:** M2 (primitives) and M3.

**Build order:**

1. **Calendar** (`/book`).
   - **The month grid:** an iPhone-style grid with a dot on each day that has open times, from the slots API (31 days at a time, with paging), and today marked.
   - **Choosing a time:** tapping a day lists its times. The time zone is shown and can be changed.
   - **The booking sheet** has the same fields as `/book`: name, email, optional phone, the qualifying questions and the consent UI.
   - **Results:**
     - `201`: the real time, the ICS and Google Calendar links, and `notify('booking-confirmed')`.
     - `202`: pending, with no time, and `notify('booking-queued')`.
     - `409`: "Just taken, pick another time", and the times refresh.
   - **If the API is down,** the GHL embed takes over, as on `/book`.
   - A package chosen in Packages arrives as `packageInterest`.
   - Reuse the booking form's logic; don't fork how it uses the contract.
2. **Mail** (`/contact`). A compose sheet:
   - To shows `service@hnst.marketing`, from settings;
   - the visitor's email, a subject and a message;
   - consent and ALTCHA, sending a `contact` lead.
   - It ends on a "Sent" state. "Use my mail app" is a `mailto:` link. A draft survives going home, in memory only.
3. **Notes** (`?app=notes`).
   - HONEST's published notes from `phoneNotes`, with a note view.
   - **New note:** the visitor's notes live in memory for the visit.
   - **Send to HONEST** asks for an email, consent and ALTCHA, and sends a `contact` lead with the note as the message.
4. **The removal page** at `/wall/remove#<id>.<token>`. It reads the id and token from the URL fragment, which never reaches server logs, asks for confirmation, and calls remove. It's noindex and stays out of the sitemap.
5. **`track()` events,** after consent: app opens, booking steps, mail sent, note sent.

**Acceptance criteria**

These are covered by `bun test` and e2e:

- validation;
- a double submit sends one lead;
- `201`, `202` and `409` each behave as above;
- consent starts unticked, and the exact displayed text is sent;
- drafts survive going home and back;
- nothing is written to browser storage.

A booking made through Calendar appears in GHL (the local stack with real GHL, using an `@example.com` email). Axe and keyboard checks pass.
